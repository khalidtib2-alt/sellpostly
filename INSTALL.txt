SellPostly Storefront Architecture - Phase 2

Apply this cumulative patch at your repository root, retaining src/, scripts/, public/ and tests/ folder paths. Previous Phase 1 separation, product pages, cart synchronization, support contact and demo artwork are included.

REQUIRED INSTALLATION
1. Extract into your repository root.
2. If a misplaced duplicate root app/ folder exists, run:
   node scripts/fix-duplicate-app.mjs
   This guarded helper backs it up outside the repository and refuses to move a root app with a layout or files without src/app counterparts.
3. Configure DATABASE_URL in your own .env.local or deployment environment. No credentials are included.
4. Run the idempotent database migration BEFORE deploying the updated application:
   npm run db:init
   The script executes the schema's statement-breakpoint blocks atomically and verifies Phase 2 columns.
5. Run:
   npm run build
   npm test
6. Deploy using your normal process. This patch has not been deployed and the live Neon database has not been migrated.

PUBLIC LINKS AND CATALOGS
/s/<slug>/affiliate and /s/<slug>/personal are independent storefronts under the existing seller account. Separate affiliate_catalog and personal_catalog JSON columns retain both published inventories. Publishing one does not overwrite the other. A never-used mode starts empty; existing catalogs migrate into their matching mode.
/shop displays both share cards, each with Copy Link and Social Share. These actions publish the corresponding device-saved catalog before sharing. Missing local catalogs can be restored from Neon. An inactive local mode is retained independently.
Personal product links remain /s/<slug>/product/<productId> and always read personal_catalog, regardless of which shop was most recently published. Their Back to Store link points to the personal alias. Existing /s/<slug> links retain compatibility with the last published catalog.

PAYMENT SETTINGS
In Personal Seller mode, enter the Seller USDC Wallet Address (Polygon), seller email and COD/USDC-escrow preferences, then Save Payment Settings. These persist in shops. The seller wallet is a payout destination only: buyers still pay NEXT_PUBLIC_ESCROW_WALLET, the platform Polygon escrow wallet. Existing Pro and Admin authentication and Admin-assigned hold periods are preserved.

COD ORDERS
POST /api/orders/cod validates the published personal catalog, current prices, selected quantities, buyer email, phone and delivery address. It records payment_method=COD, escrow_status=NONE, USD/COD accounting, zero escrow commission, and no payment verification or release deadline. Stable request IDs prevent duplicate retry submissions. COD cannot enter crypto escrow or fund seller payouts. Current recorded COD prices must be plain USD-compatible prices; unsupported currencies/token-denominated prices require seller correction.
COD is hidden and rejected when disabled. Local/snapshot previews cannot create recorded orders until published. Seller tracking updates mark COD orders shipped; COD records appear in Orders while crypto balance metrics remain separate.

EMAILS AND TRACKING
Set RESEND_API_KEY and a verified EMAIL_FROM sender to enable delivery. Reply-To is sellpostly.support@gmail.com. Set a valid seller email in Payment Settings (or the existing subscription notification settings) so seller notices have a destination. Buyer checkout now collects an email; historical contact-based order lookup remains supported. Set notification language preferences for localized seller emails.
- COD recorded: confirmation to buyer and seller.
- Admin Confirm Funds Arrived: buyer escrow-protection receipt plus seller shipping-ready notice.
- Seller tracking/carrier/note update: buyer delivery email. Revisions generate a new notification.
- Admin Release Escrow Funds: seller release notice with net amount and Polygon payout address.
Emails use committed database facts, escaped EN/FR/AR HTML and plain text, and per-recipient/event idempotency. Missing Resend configuration skips email without failing the saved order. Provider errors are logged without rolling back business updates.
Admin release remains an accounting action. No code signs or sends cryptocurrency; the release email explicitly states that the on-chain transfer is handled separately. Existing hold deadlines and buyer-confirmed force-release checks still apply.
Configure NEXT_PUBLIC_APP_URL=https://sellpostly.vercel.app (or your canonical custom domain) for production links in emails. Never use a preview URL. Keep the existing NEXT_PUBLIC_ESCROW_WALLET/Polygon configuration for live crypto checkout.

ADMIN AND SELLER DASHBOARDS
Admin order rows show the seller payout wallet with Copy Address and the buyer email. Confirm Funds Arrived and Release Escrow Funds apply only to crypto orders. COD is labeled as non-escrow and cannot use those actions. Seller fulfillment supports tracking number, shipping carrier and delivery/digital-key notes.
