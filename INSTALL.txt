SellPostly Distinct Storefront Templates + Chrome Extension 1.0.3

WEBSITE PATCH
Extract this bundle into your repository root, preserving src/, scripts/, tests/, public/ and chrome-extension/. This is cumulative with Phase 1/2, product pages, cart sync, support contact and demo artwork. Original checkout was not modified and nothing was deployed.

If a misplaced root app/ directory exists, run the guarded backup repair:
node scripts/fix-duplicate-app.mjs

If Phase 2 database columns have not yet been applied, run npm run db:init using your own DATABASE_URL before deploying. This design update stores hero, palette and optional stock settings in the existing catalog JSON. It does not require additional columns beyond Phase 2. The included idempotent schema preserves independent empty-mode design defaults.

Run npm run build and npm test, then deploy using your normal process.

TWO TEMPLATES
Affiliate (/s/<slug>/affiliate and Affiliate preview): a magazine-style curator hero, featured editorial pick, numbered photography cards, actual-description highlight bullets, category/audience filters, real compare-at discount calculations, and direct sponsored View Best Deal links. No cart, crypto, COD or escrow UI appears in the buyer Affiliate layout. Verified Store is shown only for an Admin-verified store; the template does not claim each deal is independently verified.

Personal (/s/<slug>/personal and Personal preview): a boutique hero, brand typography, Admin verification and escrow/payment indicators tied to configuration, hover image zoom, quantity-aware Quick View, full Product Landing Page links, and a slide-out Shopping Bag. Existing escrow, recorded COD and cart persistence remain connected.

In Builder, choose the shop type and edit Template Design: headline, subtitle, hero image URL, accent palette and background theme. Settings persist independently in each catalog and through published/snapshot links. Preview Template controls let you switch directly between both designs. Imported seller photos remain uncropped with contained product frames; dark themes use a white image frame.

STOCK
Stock is optional and entered by the seller; no stock quantity is invented or scraped. Zero stock disables buying actions in the buyer template. Checkout rejects quantities exceeding the configured stock. This is a manual availability/quantity limit, not an inventory reservation or automatic decrement system.

EXTENSION 1.0.3
The bundle contains a standalone SellPostly-Extension-1.0.3.zip. Extract it into a separate folder and use Chrome -> chrome://extensions -> Developer mode -> Load unpacked, choosing the folder containing manifest.json. If updating an existing unpacked install, reload that folder and verify version 1.0.3.

The Destination Store selector above Send to My Shop (Pro) offers Affiliate Deals Shop and Personal Seller Shop and remembers the selection. Category, audience, price, photo, description and optional stock travel in the existing short-URL localStorage/postMessage bridge.
- Affiliate destination: the complete external affiliate URL, including Amazon tag and campaign parameters, is preserved.
- Personal destination: store tracking parameters are removed as before, and the product enters only the Personal catalog.
The website archives the outgoing catalog, consumes the import once, switches to the target category and template preview, and also handles imports arriving after the builder has mounted. Legacy imports without a destination keep their existing active-mode behavior. Pro activation still happens on the website; no license bypass was added.

The extension keeps activeTab/scripting/storage permissions only. The known frontend allowlist and vercel.com rejection remain intact. The extension configuration fallback now uses https://sellpostly.vercel.app, including installed static shortcut links. Use NEXT_PUBLIC_APP_URL for your canonical deployment; do not use a Vercel dashboard or preview URL.
